# Support

## Operator support

For a functional defect, open a GitHub defect report with the release, workflow, browser/OS, minimal synthetic reproduction, expected result, and observed result. Do not attach production records or workspace backups.

For a vulnerability, follow [SECURITY.md](SECURITY.md). For receiving-system rejection, retain the lossless IN KEEPING package, exact receiving product/version, import profile, warnings, and a synthetic rejected row or record.

## Recovery first

Before clearing browser data, changing the canonical domain, reinstalling a browser profile, or rolling back a deployment:

1. Save the named workspace if it is current and valid.
2. Download a plaintext workspace backup and the Technical Report.
3. Store them under the institution’s approved access, encryption, retention, and disposal controls.
4. Verify recovery in a separate named workspace or nonproduction profile.

The application has no server copy of workspace content and cannot recover data removed by browser eviction, profile deletion, device loss, or an origin change.
