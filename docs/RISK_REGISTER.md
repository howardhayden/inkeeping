# Risk register

## Use of this register

This is the product risk register for the current static, browser-local design. Ratings are qualitative planning judgments, not quantitative probability estimates.

- **Likelihood:** Low, Moderate, or High within the stated use case.
- **Impact:** Low, Moderate, High, or Critical to confidentiality, integrity, availability, accessibility, or continuity.
- **Residual:** the condition after implemented application controls, assuming the operating conditions in the threat model.
- **Disposition:** Mitigate, Accept with conditions, Transfer/govern externally, or Avoid.

The deploying institution must assign named owners and acceptance authority. Repository role names below identify the kind of owner; they are not evidence that an institution has accepted a risk.

## Release blockers

The following conditions block a production release:

1. any Critical- or High-impact risk lacks a documented owner and required external control;
2. `npm run release:check` does not complete successfully on the release commit;
3. live canonical-host headers or network behavior differ from the source-controlled policy;
4. the institution has not approved intended data classes and plaintext handling;
5. the canonical-origin migration/restore procedure has not been rehearsed when existing work must move;
6. safety-critical flows have not received manual keyboard and accessibility review; or
7. a parser, identity, storage, incident-closure, outward-output, or public-projection change lacks updated negative and boundary tests; or
8. an output path can bypass the required integrity, freshness, sample, finding, closure, or publication-state gate without an explicitly documented recovery purpose.

## Review cadence and change triggers

Review this register at each release and at least annually while deployed. Immediate review is required after a security incident, dependency advisory, browser/storage behavior change, hosting/account change, new import/export format, new data category, new remote connection, altered Public Notice projection, or changed storage/audit construction.

Closing a risk requires evidence in the repository or an external control record. Rewording the risk is not closure.
